# SignaCulture research

Everything experimental lives here: research code, plans, results, logs and
private run outputs. Product code (`backend/`, `frontend/`, `webcam/`,
`motion_worker/`) and product documentation (`docs/`) are outside this folder.

**Start here:** [STATUS.md](STATUS.md) (current requirement-by-requirement
audit) and [RESULTS.md](RESULTS.md) (every experiment, measured results and
limits). Machine-checked evidence: [CURRENT_RESEARCH_STATUS.json](CURRENT_RESEARCH_STATUS.json),
regenerated by `python3 scripts/audit_research_status.py`.

**Overall finding:** no experiment has produced a reliable French → sign
translator or a linguistically validated signing avatar. The limiting factor
is aligned, reviewed supervision, not model size or GPU. No qualified
France-LSF or LSFB review exists yet.

## Layout

```

├── STATUS.md  RESULTS.md  README.md  PATH_MAP.json
├── <track>/            reports (.md/.json) for one research question; raw logs in <track>/logs/
├── runs/               registered run metrics and predictions (read by the Studio's Research panel)
├── code/               all research code
│   ├── training/       text-to-gloss, transitions, LSFB/GeoQuery pipelines, catalog tools
│   ├── src/            SignVerse data, motion in-betweening, mT5 scripts
│   ├── experiments/    MediaPipe motion extraction prototype, emotion2vec CLI
│   ├── normalization/  anatomy-aware motion normalization (PyTorch)
│   ├── signaculture-direct-fsl/   caption → pose pilot (self-contained project)
│   └── tests/          research test suites
├── private/            gitignored run outputs, adapters and review packs
└── archive/            historical snapshots
```

## Running research code

Run commands from the repository root with the research code on the Python
path. Commands recorded in older reports (`python -m training.…`) work
unchanged this way:

```bash
export PYTHONPATH=research/code
python -m training.lsfb_cont.summarize_seed_replication
python -m pytest research/code/tests -q
```

`pytest.ini` already sets this path for test runs. `signaculture-direct-fsl`
is run from its own folder, as its README describes.
